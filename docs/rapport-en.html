1 Overview

ClearNet is a decentralized netting engine: a shared ledger of receivables/debts (Neo4j graph database) enriched with an on-chain netting engine (CLRN ERC20 token + net positions) that only uses the net balance to be settled, backed by a mobile application.

Mobile applicationReact Native 0.72 · Expo SDK 49

Login / registration, CLRN transfer, history with direction, one-tap partner demo mode.

REST APINestJS 10 · JWT · class-validator

Auth, users, transactions, companies/sectors, on-chain bridge, oracles, demo. Global /api prefix, CORS, strict ValidationPipe.

Graph databaseNeo4j 5.26 (Docker)

Nodes :User, :Transaction, :Company; SENT/RECEIVED relationships; IDs via randomUUID().

Smart contractsSolidity 0.8.19 · OpenZeppelin 4.9

ClearNetToken (CLRN), CompensationEngine (netting + optional ZK gate), ChainlinkPriceFeed.

2.1 Transaction flow

  1. The mobile app calls POST /api/transactions (JWT) with {toEmail, amount, note?}.
  2. The backend validates the DTO, rejects self-transactions, then runs assertCompliance() (ITAR/OFAC — no-op if ITAR_ENABLED=false).
  3. The :Transaction node is created in Neo4j with the SENT/RECEIVED relationships.
  4. If the bridge is active (ONCHAIN_ENABLED=true), settleCompensation() is called fire-and-forget (the HTTP response is never blocked); the result (onchainHash, onchainStatus SUCCESS/FAILED) is written on the node.
  5. On-chain settlement requires netPositions[from] ≥ amount and netPositions[to] ≤ 0 — only the net balance is used.

4.2 Security and global hardening

  • JWT HS256 (JWT_SECRET, expiration JWT_EXPIRES_IN default 7 days), Bearer strategy (passport-jwt ^4.0.1).
  • bcryptjs (pure JS, no native compilation — deliberate choice for Mac/Windows), 10 rounds.
  • Global rate-limiting (@nestjs/throttler): 100 req/60 s by default, hardened @Throttle on /auth/* (login 5/60 s, register 10/60 s); 429 message in French.
  • ValidationPipe strict: whitelist + forbidNonWhitelisted (unknown fields rejected).
  • Global CORS (origin: true, credentials: true) and /api prefix.
  • Password never exposed (passwordHash stripped from responses).
  • Clean shutdown of the Neo4j driver (onApplicationShutdown hook).
  • Demo API protected by X-Demo-Key header (DEMO_API_KEY).

5 On-chain bridge (backend → contracts)

@Global() blockchain module — ethers v6 bridge between the API and the contracts, introduced in V1.1 (recordPositionChange) then reworked in V1.2 as asynchronous settlement (settleCompensation).

V1.2 scaling caveat (documented): the ZK circuit works in micro-CLRN (×1e6) while the on-chain ledger is in wei (×1e18); the ZK gate validates the assertion (amount ≤ cap + commitment), exact micro/wei equality being a next-phase refinement (sufficient for a testnet).

6.2 ZK circuit (circuits/transaction.circom)

  • Private inputs: sender, receiver, amount; public: maxAmount; output commitment = Poseidon(sender, receiver, amount).
  • Constraints: amount > 0 (Num2Bits 64 bits + IsZero), amount ≤ cap (LessThan), binding commitment.
  • Artifacts produced by scripts/generate-zk-keys.sh: transaction.wasm, transaction.zkey, verification_key.json, contracts/Verifier.sol (configurable PTAU power, entropy contribution).
  • Backend verification: on-chain via VERIFIER_ADDRESS (off-chain fallback), then off-chain groth16.verify — by ZkProofService (snarkjs ^0.7.4).
