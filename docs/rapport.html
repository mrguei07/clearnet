1 Vue d'ensemble

ClearNet est un moteur de compensation (netting) décentralisée : un registre partagé des créances/dettes (base de graphes Neo4j) enrichi d'un moteur de compensation on-chain (token ERC20 CLRN + positions nettes) qui ne mobilise que le solde net à régler, adossé à une application mobile.

Application mobileReact Native 0.72 · Expo SDK 49

Connexion / inscription, transfert CLRN, historique avec direction, mode démo partenaire en un geste.

API RESTNestJS 10 · JWT · class-validator

Auth, users, transactions, entreprises/secteurs, pont on-chain, oracles, démo. Préfixe global /api, CORS, ValidationPipe strict.

Base de graphesNeo4j 5.26 (Docker)

Nœuds :User, :Transaction, :Company ; relations SENT/RECEIVED ; IDs via randomUUID().

Smart contractsSolidity 0.8.19 · OpenZeppelin 4.9

ClearNetToken (CLRN), CompensationEngine (netting + gate ZK optionnel), ChainlinkPriceFeed.

2.1 Flux d'une transaction

  1. Le mobile appelle POST /api/transactions (JWT) avec {toEmail, amount, note?}.
  2. Le backend valide le DTO, refuse l'auto-transaction, puis exécute assertCompliance() (ITAR/OFAC — no-op si ITAR_ENABLED=false).
  3. Le nœud :Transaction est créé en Neo4j avec les relations SENT/RECEIVED.
  4. Si le pont est actif (ONCHAIN_ENABLED=true), settleCompensation() est appelé en fire-and-forget (la réponse HTTP n'est jamais bloquée) ; le résultat (onchainHash, onchainStatus SUCCESS/FAILED) est écrit sur le nœud.
  5. Le règlement on-chain exige netPositions[from] ≥ amount et netPositions[to] ≤ 0 — seul le solde net est mobilisé.

4.2 Sécurité et durcissement global

  • JWT HS256 (JWT_SECRET, expiration JWT_EXPIRES_IN par défaut 7 j), stratégie Bearer (passport-jwt ^4.0.1).
  • bcryptjs (pur JS, aucune compilation native — choix délibéré pour Mac/Windows), 10 rounds.
  • Rate-limiting global (@nestjs/throttler) : 100 req/60 s par défaut, @Throttle renforcé sur /auth/* (login 5/60 s, register 10/60 s) ; message 429 en français.
  • ValidationPipe strict : whitelist + forbidNonWhitelisted (champs inconnus rejetés).
  • CORS global (origin: true, credentials: true) et préfixe /api.
  • Mot de passe jamais exposé (suppression de passwordHash dans les réponses).
  • Fermeture propre du driver Neo4j (hook onApplicationShutdown).
  • API démo protégée par en-tête X-Demo-Key (DEMO_API_KEY).

5 Pont on-chain (backend → contrats)

Module @Global() blockchain — pont ethers v6 entre l'API et les contrats, introduit en V1.1 (recordPositionChange) puis refondu en V1.2 en règlement asynchrone (settleCompensation).

MécaniqueDétail
IdentitéAdresse déterministe par email : '0x' + keccak256(email.toLowerCase()).slice(-40) — exploité aussi par validate-sepolia.ts pour la cohérence
ExécutionPOST /api/transactions → blockchainService.settleCompensation(from, to, amount) en fire-and-forget ; résultat écrit sur le nœud (onchainHash, onchainStatus)
ABIsFragments de chaînes dans blockchain.constants.ts (TOKEN_ABI : ERC20 + mint/burn/burnFrom ; ENGINE_ABI : updatePosition/netPositions/settle/settleWithProof/setZkSettings/admin/zkRequired/zkbVerifier/maxAmount) ; TOKEN_DECIMALS = 18
Fallback RPCDEFAULT_RPC_URL = https://ethereum-sepolia-rpc.publicnode.com
Méthodes du servicetokenBalanceOf · getTokenBalance · mintTo · getTokenInfo · approve · getAllowance · getNetPosition · recordPositionChange · settleCompensation · settleCompensationWithProof · configureZk
ErreursOnchainBridgeError('disabled' | 'not-initialized') — dégradation douce, jamais bloquante pour la requête HTTP
Caveat d'échelle V1.2 (documenté) : le circuit ZK travaille en micro-CLRN (×1e6) alors que le ledger on-chain est en wei (×1e18) ; le verrou ZK valide l'affirmation (montant ≤ plafond + engagement), l'égalité exacte micro/wei étant un raffinement de phase suivante (suffisant pour un testnet).

6.1 Contrats

ContratRôleFonctions clés
ClearNetToken (CLRN) ERC20 (OpenZeppelin 4.9.3) — l'actif du réseau, Ownable mint(to, amount) (onlyOwner) · burn(amount)

Verifier.sol Généré par snarkjs (generate-zk-keys.sh) — non versionné, écrasé à chaque run —

Invariants de settle : netPositions[from] ≥ amount et netPositions[to] ≤ 0, puis Compensated(from, to, amount). setZkSettings active le contrôle de preuve (défaut off).

6.2 Circuit ZK (circuits/transaction.circom)

  • Entrées privées : sender, receiver, amount ; publique : maxAmount ; sortie commitment = Poseidon(sender, receiver, amount).
  • Contraintes : montant > 0 (Num2Bits 64 bits + IsZero), montant ≤ plafond (LessThan), engagement liant.
  • Artefacts produits par scripts/generate-zk-keys.sh : transaction.wasm, transaction.zkey, verification_key.json, contracts/Verifier.sol (puissance du PTAU paramétrable, contribution d'entropie).
  • Vérification backend : on-chain via VERIFIER_ADDRESS (repli off-chain), puis off-chain groth16.verify — par ZkProofService (snarkjs ^0.7.4).
